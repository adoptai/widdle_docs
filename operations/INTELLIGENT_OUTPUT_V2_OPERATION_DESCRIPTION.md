Define an INTELLIGENT_OUTPUT_V2 operation step in a JSON workflow language that uses a Large Language Model (LLM) to intelligently format data into user-facing markdown output with automatic header and formatting rule generation.

Basic Structure:
{
  "id": string,
  "operation": "INTELLIGENT_OUTPUT_V2",
  "input": string,
  "key_mapping_instructions": string (optional),
  "preferred_llm": string (optional),
  "table_header_hints": string (optional),
  "table_rows_limit": integer (optional, default: 20)
}

Key Features:
- Uses LLM to automatically generate human-readable column headers from JSON keys
- Uses LLM to automatically identify and generate formatting rules for dates, currency, numbers, and enums
- Generates markdown tables with proper column ordering based on user query and hints
- Takes output from a previous workflow step as input (must be an array)
- For arrays with more than one row: generates a markdown table showing up to table_rows_limit rows (default: 20), with full data available for download
- Always returns markdown format output
- Requires unique operation ID
- Requires LLM configuration to be available

Parameters:
- input: ID of a previous workflow step that contains the data to be formatted (required, must be an array)
- key_mapping_instructions: Optional hints for the LLM on how to map JSON keys to human-readable names. Split multiple instructions by '. ' (period space) - they will be converted to newlines.
- table_header_hints: Optional hints for the LLM on which columns to display and in what order. Split multiple hints by '. ' (period space) - they will be converted to newlines.
- preferred_llm: LLM to use for header and formatting rule generation (optional, default: CLAUDE_4_5_HAIKU)
- table_rows_limit: Maximum number of rows to display in the output table (optional, default: 20)

How It Works:
1. Analyzes sample data row to identify relevant fields
2. Uses LLM to generate human-readable column names based on user query and hints
3. Uses LLM to identify fields needing formatting (dates, currency, numbers, enums) and generates formatting rules
4. Applies formatting rules to the data
5. Generates markdown table with proper column ordering
6. Optionally generates a header message summarizing the table

Examples:

1. Formatting Contract Data with Automatic Headers:
Input from previous step "filtered_contracts":
[
  {"vendorName": "Spendflo", "cost": 5000.00, "status": "ACTIVE", "expirationDate": "2025-12-31"},
  {"vendorName": "Acme Corp", "cost": 3000.00, "status": "PENDING", "expirationDate": "2025-06-30"}
]

Operation:
{
  "id": "formatContracts",
  "operation": "INTELLIGENT_OUTPUT_V2",
  "input": "filtered_contracts",
  "table_header_hints": "Show vendor name, cost, status, and expiration date. Do not show any UUID fields."
}

Output:
The LLM will automatically:
- Generate headers like "Vendor Name", "Cost", "Status", "Expiration Date"
- Identify cost as currency and format it appropriately
- Identify expirationDate as date and format it
- Identify status as enum and create a mapping
- Order columns logically
- Generate a markdown table with proper formatting

2. Formatting with Custom Instructions:
Operation:
{
  "id": "formatContracts",
  "operation": "INTELLIGENT_OUTPUT_V2",
  "input": "filtered_contracts",
  "key_mapping_instructions": "Map vendorName to 'Vendor'. Map cost to 'Annual Cost'.",
  "table_header_hints": "Display vendor first, then cost, then status. Ignore internal ID fields.",
  "table_rows_limit": 10
}

Output:
The LLM will use the instructions to generate appropriate headers and ordering, while still automatically identifying formatting needs.

Implementation Notes:
- The 'input' field must reference a valid ID from a previous workflow step
- Input data must be an array (list of objects)
- Empty arrays will return a helpful message generated by the LLM
- Single objects are automatically wrapped in an array
- Nested arrays are not supported (only one level of array is allowed)
- Header generation and formatting rule generation run in parallel for better performance
- The LLM uses the user query (from workflow_arguments.user_query) to determine relevant fields
- Column ordering is determined by the LLM based on user query and table_header_hints
- Formatting rules are automatically applied using LocaleManager for proper locale and timezone handling
- The operation always returns markdown format tables
